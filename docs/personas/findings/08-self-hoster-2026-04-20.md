## Outcome
Partial / graceful-bounce. Dev leaves with an accurate mental model ("SaaS-only for now, run by a real person, no repo link yet") and no trust breaks, but also no conversion.

## Friction found
- [medium] F1 — No GitHub link, no "About", no team page. Dev cannot verify who is behind the project before giving an email. Mitigated by the personal gmail in ToS (a single data point of human-ness), but below the threshold Dev expects. Footer in `src/pages/LandingPage.tsx`.
- [medium] F2 — The product has no story for the self-hoster segment anywhere on the site. Landing sells to founders and agent developers only. Given that `docs/go-to-market.md` still describes an "Open Core Later" plan and `docs/vision.md` documents a docker-compose stack, the public site is silent on this audience entirely. Dev would either bounce before arriving or leave without engagement.
- [low] F3 — `viktor.cihal@gmail.com` is now the load-bearing contact for ToS. If the project grows, a `legal@telarchy.com` forwarder is cheap insurance; personal gmail is legible as early-stage but looks odd next to a Delaware governing-law clause. Listed as low because it's likely intentional.
- [low] F4 — Inconsistent internal docs: `README.md:3` still describes Telarchy as "a self-hostable metrics governance platform" while `README.md:153` says "All rights reserved. An open-source release is planned for the future but not currently available." README is in a private repo today so Dev never sees this, but any future publication of the repo would make these two lines read as contradictory. Either soften line 3 to "Metrics governance platform with prediction markets..." or drop the self-host adjective until the image is public.
- [L-1] localhost-only — `npm run dev` against the local DB shows a marketplace dominated by QA-seed workspaces at flat 50% / baseline prices. Not a user-facing finding (prod looks different), but relevant for anyone testing the self-hoster persona against localhost: simulate on prod, or seed the local DB with varied trades, or the finding pattern swings toward "dead product" when the truth is "QA-seed-only". Documented here to save the next run.

## What worked
- No false open-source or self-host promises anywhere user-visible. This is a real change vs last session; the retraction sweep held.
- ToS / Privacy render cleanly with no unresolved placeholders. A self-hoster who reads them would leave more trusting, not less.
- Prod marketplace has varied real workspaces with real non-default prices. Passes the "is this thing alive?" check.

## Would they come back?
Maybe. Not for the product as sold. If the landing added a one-liner like "Open-source and self-hostable coming soon: [planning doc]" and a footer link to an "About" or a public GitHub-based roadmap, Dev would bookmark. Today the site says nothing to them, so there's nothing to bookmark.

## Recommended changes
- [medium] Add a single footer link "About" or "Who we are" that surfaces: name of maker, a one-line origin story, and a clear status line for open-source / self-hosting plans. The roadmap is already documented in `docs/go-to-market.md` and `docs/vision.md`; the public version can be a 3-paragraph page at `/about`. Cost: 1 hour. Captures the self-hoster segment without committing to a release date.
- [low] Reconcile `README.md:3` with `README.md:153`. Drop "self-hostable" from the subtitle or rewrite it as "Metrics governance platform with prediction markets; open-source and self-host release planned."
- [low] Either move ToS §12 Contact to a project-owned address (`legal@telarchy.com` or similar) or accept the personal-gmail signal as intentional. Flagging so the user can decide.
