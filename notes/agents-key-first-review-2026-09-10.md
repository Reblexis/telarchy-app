# Agents key-first design review

The owner requested immediate key availability and an independent review of both tabs, aiming for 9+/10. Key creation remains an explicit action, not a side effect of visiting the page. The generated secret is displayed immediately in place.

A separate critic, briefed with audience, tasks, actual screenshots and the shared rubric but not the target score, reviewed repeated iterations. Scores progressed from 7.7 to 8.0, 8.3 and 8.5 overall. At 8.5 the critic found no remaining specific issue in the ordinary flows. A larger-list check then identified that creation controls and fresh secrets belonged above existing keys, and that personal keys needed a shortcut when many bots preceded them.

Changes address visible key creation, named workspace selection, honest restriction metadata, copying guidance, compact empty states, keyboard-friendly identity selection, manual clipboard order and the distinction between a connection and a running agent. Research previews remain available without creating a key. Optional trading upgrades and further funding remain available as secondary actions.

The critic independently ran isolated browser fixtures covering personal and bot key creation, key-copy feedback, named workspaces, both tabs and identity shortcuts, manual instructions, anonymous keyboard selection, and anonymous prompt copying without mutations. Desktop/mobile screenshots covered populated, empty, anonymous, ready, manual and expanded management states. A larger-list fixture covered 15 bots and 12 keys including long labels without overflow.

These are heuristic ratings of local rendered flows and fixture behavior, not measured user satisfaction, real authentication, backend execution, terminal execution or a production deployment claim. The 9+ target is not established by the scores recorded above.
